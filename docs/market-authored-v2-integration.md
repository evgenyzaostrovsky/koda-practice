# Авторский курс KODA Market, revision market-authored-v2

Источник курса — полный авторский пакет, сохранённый побайтно в `content/datasets/koda-market/authored-v2`. Старый `KODA_Market_full_task_bank.md` не используется для генерации. `scripts/parse_market_authored.py` сохраняет все 115 шагов, номера, ситуацию, задание, три подсказки, проверку и разбор без редакторского пересказа. Хеши файлов и привязка каждого шага к стабильному ID находятся в `content/market_authored_v2.json` и `reports/market-authored-v2-map.json`.

`scripts/import_market_authored.py` объединяет авторский текст, индивидуальные исполняемые решения Python/SQL из `scripts/market_authored_references.py`, настройки учебных симуляторов из `content/market_native_v2.json` и отдельно написанные статьи/шпаргалки из `market_teaching_a.json`, `market_teaching_b.json`, `market_teaching_v2.json` в этом порядке. Совместимый вход `scripts/integrate_market.py` вызывает этот импорт. Повторный импорт не меняет область миграции.

Проекция `apps/web/public/market-course.json` содержит 19 уроков и ровно 115 различных заданий в авторском порядке: GroupBy 1–12, Python 13–82, SQL 83–92, Excel 93–102, Power BI 103–112 и итоговые кейсы 113–115. Учебные единицы сохраняют максимум десять заданий; проекция курса объединяет несколько единиц в один урок без создания второй копии задания.

Все 200 исходных идентификаторов базового банка сохранены. Неиспользуемые старые задания Market перечислены в явной миграции. Архивная тема и KnowledgeUnit `market-selection` сохраняют стабильные идентификаторы, статью и шпаргалку с `knowledge_only: true`, без искусственных задач. Проверка каталога допускает пустоту только для такой явно архивной пары. `filtering-002` остаётся базовым заданием о доставке; старое включение в проект исключено, его прогресс включён в архив обновления.

`content/market_revision.json` определяет точные затронутые, удалённые и действующие ID. Публичная копия и артефакт сборки `apps/web/src/content-revision-manifest.json` генерируются из него. Награды не удаляются. Реализацию архива прогресса проверяет отдельный владелец.

Авторское условие не дополняется скрытыми требованиями. Поле `answer_contract` отдельно фиксирует имя ответа, столбцы и неоднозначные технические детали. Сравнение результатов использует разрешённые альтернативы: имена Series, небольшой числовой допуск, порядок равных значений, корректный выбор на границе рейтинга. Пустые ответы при проверке повторов, отсутствующего клиента и пробелов дополнительно проверяются на отдельной изменённой копии; исходные CSV остаются неизменными. Пять аналитических выводов проверяются по числовым фактам, а не по совпадению текста.

Статьи принадлежат KnowledgeUnit целиком. Расширенные единицы SQL/Excel/Power BI покрывают больше восьми самостоятельных приёмов, поэтому аудит допускает до шестнадцати только для этой авторской revision; требования к компактности каждой записи, независимому написанию и покрытию статьёй сохраняются. Это не связано с количеством задач.

Excel и Power BI — явно обозначенные учебные симуляторы: проверяются формулы, расчёты, модель, фильтры и воспроизводимые действия. Они не создают файлы `.xlsx`/`.pbix` и не заявляют полную совместимость с настольными приложениями. SQL остаётся в изолированном task-worker, свободная практика — в браузерном Pyodide worker.

Обязательная проверка интеграции: `npm run content:sync`, `npm run content:audit`, независимые тесты соответствия источнику и пользовательских сценариев. Примеры статей дополнительно проверяются отдельным набором авторских тестов; это не заменяет независимую QA.
