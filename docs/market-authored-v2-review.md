# KODA Market authored bank v2 — product decision

The Founder authorized replacing the previous Market interpretation with KODA_Market_Codex_upload.zip and allowed progress removal. The authoritative source is the final master prompt, groupby tasks 1–12, and seven completed-task files 13–115. The old full_task_bank outline is obsolete.

## Integrated decision

Import exactly 115 distinct authored source steps in their numbered order. Preserve situations, instructions, three hints, source validation guidance and analysis; any necessary executable answer contract is visibly separate. Canonical CSV values remain unchanged. Reuse stable identities for equivalent existing objectives; new objectives receive new IDs. Obsolete Market objectives require an explicit retirement/migration map. Preserve all original foundation identities and unrelated work.

Keep the approved compact interface and achievement room. Python and SQLite run in the existing task subprocess; free practice remains the isolated browser Pyodide worker. Excel and Power BI remain explicitly bounded educational simulators, extending real calculated controls, formula/model checks, filter context, clickable visuals and clear/reset behavior required by the source. Matching output numbers or a self-reported checkbox is insufficient evidence of a taught interaction. Native Office/Power BI compatibility and file export are not claimed.

Reset affected Market task progress once per content revision, including reused foundation IDs whose objectives change. Archive prior evidence before clearing active completion/drafts, preserve unrelated tasks, accounts and private datasets, and prevent stale cloud drafts from resurrecting old completions. Preserve previously earned trophies as historical awards; changing a course does not revoke already earned recognition. Task XP/activity must reflect current retained task evidence. Real remote migration must not be reported as verified without an authenticated environment.

Cloud reset uses revision-qualified internal storage keys for affected tasks because the existing Supabase task IDs are TEXT without catalog foreign keys. Public task identities and URLs stay unchanged. Legacy rows remain historical and inactive; new writes use the current revision namespace, and reads decode only the active namespace before progress/history pagination. This avoids a privileged remote schema migration, preserves new progress across devices and isolates delayed legacy writes. Local SQLite and browser stores still archive affected old evidence once. The Tech Lead independently approved this bounded design.

## Final runtime findings

Independent QA reproduced mobile task 96 panels expanding to 1859 pixels beneath a 390-pixel clipped root. The Tech Lead traced intrinsic table sizing through a mobile flex column using align-items:start. The scoped fix stretches/constrains the panels and local table wrappers; full tables retain internal horizontal scrolling. Acceptance checks must measure descendant panel bounds and access to the final column, rather than document.scrollWidth alone.

The actual Sandbox Restart scenario also repeated a 15-second timeout. Tech Lead and QA independently traced the library preparation boundary: NumPy/pandas packages were downloaded before ready, but their first interpreter import occurred after the user execution watchdog started. The bounded decision imports these vetted core libraries before ready, updates the worker version and preserves the 15-second arbitrary-code limit and browser Worker isolation. Repeated real Restart, DataFrame/print output, timeout and recovery are required release checks; attributing all observed delay to that import is not assumed without runtime evidence.
