## Эталон языка задач

Задание пишется человеческим языком и не перегружается техническими названиями колонок.

Плохо:

> Сгруппируйте `orders` по `city` и посчитайте общую выручку `revenue` для каждого города. Сохраните результат как `Series`.

Хорошо:

> Сгруппируйте заказы по городу и посчитайте общую выручку для каждого города. Сохраните ответ в переменную result.

Правила:

- в основном тексте задания не использовать backticks и внутренние имена колонок без необходимости;
- говорить «заказы», «клиенты», «каналы», «города», «выручка», а не `orders`, `customer_id`, `channel`, `revenue`;
- технические имена оставлять в подсказках, примерах кода, схеме результата и автоматической проверке;
- не писать «разделите строки», «объедините строки» и другие неестественные формулировки;
- использовать нормальные глаголы: «сгруппируйте», «посчитайте», «оставьте», «отсортируйте», «сравните»;
- одна задача должна проверять один основной навык и максимум один уже знакомый навык.

## Формат каждой задачи

Каждая задача обязана содержать:

1. короткую рабочую ситуацию;
2. понятное задание без лишнего кода;
3. конкретный датафрейм или ссылку на общий датафрейм;
4. ожидаемый тип и форму ответа;
5. три подсказки;
6. короткий разбор после решения;

1. первая объясняет, какой результат нужен;

Не выдавай готовый код в первой подсказке. Не прячь смысл задачи за терминологией.
